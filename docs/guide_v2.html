1. Project at a Glance

Vadaanya Talent Test 2026 transitions a five-year-old, paper-based rural talent test onto a resilient, automated cloud platform. It registers 8,000 government school students across Anantapur and Sri Sathya Sai districts, manages exam center allocations, generates verifiable hall tickets, and prepares OMR-ready data for exam day.

1.1 What is Changing

Before (Manual Paper Process) After (Vadaanya 2026 Cloud Platform)
Physical paper forms filled by hand; data transcription errors. Mobile-first web form with instant Verhoeff validation and database auto-save.
Incomplete forms discarded or lost due to intermittent connectivity. Database-Backed Drafts: Uncompleted forms saved in DB as PENDING and auto-resumed on Aadhaar re-entry.
Manual alphabetical sorting across mandals in spreadsheets. Automated spatial and mandal clustering with gender-segregated exam center assignments.
Hand-delivered hall tickets requiring weeks of logistical delay. Instant PDF hall tickets with QR verification, WhatsApp/SMS links, and one-click Headmaster bulk downloads.
Zero visibility into registration momentum or drop-off friction. Dedicated Admin Analytics Dashboard tracking funnel drop-offs, district quotas, and low-registration school red flags.

2. Rural Ground Realities & Technical Responses

The platform is engineered around the actual constraints of rural Andhra Pradesh, ensuring accessibility, data integrity, and high completion rates.

2.1 Stakeholder Personas & Realities

Rural Student
(Class 9 & 10)		 Lacks personal smartphone, computer, or email address. Official identifier is their 12-digit Aadhaar. Language is Telugu and simple English. Never require email. Use Aadhaar as sole identity and mobile number purely for notifications. Bilingual Telugu/English interface.
School POC
(Headmaster / Math Teacher)		 Registers 20 to 50 students in one sitting using one school PC, mobile phone, or local MeeSeva center. One phone number repeats across dozens of students. (50-Member Campaign Team)		 Visits remote schools with tablets/phones after District Collector launch. Network drops between 2G, 3G, and 4G. Lightweight Next.js payload (<80KB gzip). Database-backed block auto-saving ensures partially filled forms are never lost.

2.2 Problem & Technical Countermeasure Matrix

Ground Hurdle Why Traditional Systems Fail Vadaanya 2026 Architectural Solution
Phone Number Collisions Using phone numbers as a unique constraint crashes when a teacher registers 30 students. Aadhaar is the sole unique identifier. Mobile numbers are treated solely as delivery routes, permitting 1:N mapping without conflict.
Dropped Forms / Power Cuts Unstable internet causes students to lose half-filled forms, leading to abandonment. Database-Backed Auto-Save: Each block entered is immediately saved to PostgreSQL under status: PENDING. Re-entering Aadhaar auto-restores data on any device.
Duplicate Registrations Students forget they were registered by a teacher and try again, creating duplicates. Step 0 Gate Check: Entering Aadhaar immediately tells them: "You have already registered. Your Reg No is V26-ATP-B0016" without loading the form.
Lost Registration Slips Students lose paper slips or delete SMS, unable to retrieve hall tickets. Dual-Key Recovery: Hall tickets can be retrieved with Registration Number OR Aadhaar + Mobile Number.
Teacher Bulk Entry Fatigue Re-typing District, Mandal, and School 30 times causes extreme fatigue and typos. "Quick Add Next Student" Mode: Retains District, Mandal, and School in form state, resetting only student-specific fields.

4. Aadhaar Data Protection & Zero-Leakage Architecture

The Aadhaar number is sensitive Personally Identifiable Information (PII) governed by strict UIDAI regulations. Plain-text Aadhaar numbers must NEVER exist in the database, cache, or logs.

4.1 The Four Security Protection Layers

Layer Mechanism Database Field Visibility & Access
1. Deterministic Blind Index HMAC-SHA256(normalised_aadhaar, KMS_PEPPER). Pepper is stored in Key Vault, never in code. Enforces SQL UNIQUE constraint for instant $O(1)$ duplicate checks. aadhaarHash Irreversible cryptographic hash. Nobody can reverse-engineer the Aadhaar number from it.
2. Envelope Field Encryption The 12 digits are encrypted with AES-256-GCM using a customer-managed key (CMK). GCM provides authenticated encryption, instantly detecting ciphertext tampering. aadhaarEncrypted Only decryptable via air-gapped administrative script for statutory government audits.
3. Display Masking Only the last 4 digits are kept in plain text (e.g. XXXX-XXXX-5678). aadhaarLast4 Displayed on public receipts, hall tickets, and admin analytics tables.
4. Zero-Log Sanitization Middleware Next.js API middleware intercepts all outgoing logs (CloudWatch, Sentry, Azure Monitor) and strips any 12-digit sequence matching \b\d{4}[ -]?\d{4}[ -]?\d{4}\b. None Guarantees zero accidental PII leakage in debug traces or crash reports.

4.2 Input Ingestion & Normalization Snippet

import { createHmac } from "crypto";

const normalise = (a: string) => a.replace(/\D/g, ""); // extract digits only

export function deriveAadhaarFields(rawAadhaar: string, pepper: string, kmsKey: string) {
  const clean = normalise(rawAadhaar);
  // 1. Blind Hash Index for uniqueness check (O(1) duplicate prevention)
  const aadhaarHash = createHmac("sha256", pepper).update(clean).digest("hex");
  // 2. Field-Level AES-256-GCM Ciphertext via Key Management Service
  const aadhaarEncrypted = encryptWithKms(clean, kmsKey);
  // 3. Safe Display Mask for public view and hall ticket printing
  const aadhaarLast4 = clean.slice(-4);
  return { aadhaarHash, aadhaarEncrypted, aadhaarLast4 };
}

5.2 District Hard Quotas & Atomic Concurrency Control

Each district is strictly capped at 4,000 confirmed registrations (8,000 total). A two-tier locking mechanism guarantees the cap is never exceeded:

Layer Mechanism Behavior
Fast Edge Gate Redis INCR district_quota:anantapur before DB write If counter > 4,000, rejects request at edge in under 10ms with HTTP 409 "District Quota Exhausted". Reverts via DECR on rollback.
Database Guard Atomic single-statement conditional update Ensures exact count inside the SQL transaction. Zero updated rows rolls back immediately. 
BEGIN;
  -- Atomic seat reservation: check and increment in ONE atomic statement
  UPDATE districts
  SET registered_count = registered_count + 1
  WHERE name = 'ANANTAPUR' AND registered_count < quota_max
  RETURNING registered_count; -- If 0 rows returned => ROLLBACK & return HTTP 409

  -- Transition status from PENDING to COMPLETED and assign registration number
  UPDATE students
  SET registration_status = 'COMPLETED',
      registration_number = 'V26-ATP-B0016',
      completed_at = NOW()
  WHERE id = $studentId;
COMMIT;

The registration number format is engineered for clarity and ease of transcription on OMR sheets:

V26 - [DIST] - [BATCH][4-DIGIT SEQ]
Example: V26-ATP-B0016 (Anantapur, Batch B, Candidate 0016)
Component Allowed Values Description
V26 Static Prefix Identifies Vadaanya Talent Test for Year 20**26**.
[DIST] ATP or SSS Identifies District: ATP (Anantapur) or SSS (Sri Sathya Sai).
[BATCH] A, B, C, D Letter designating candidate batch (e.g. Batch A: 1–1,000; Batch B: 1,001–2,000).
[4-DIGIT SEQ] 0001 to 1000 Zero-padded 4-digit sequential integer within the batch.

7. One-Way Automated Messaging: WhatsApp and SMS

Rural communications must route through mobile numbers rather than email. A single mobile number may be associated with multiple students, requiring personalized template messages.

7.1 Architecture & Setup

  • Primary Gateway: Meta WhatsApp Cloud API via Next.js Server Actions / AWS Lambda.

10. Database Architecture & Complete Prisma Schema

The relational schema in PostgreSQL uses Prisma ORM to support draft saving (PENDING vs COMPLETED), field-level encryption, atomic district seat counters, and click-to-call phone tracking.

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

enum RegistrationStatus {
  PENDING    // Incomplete draft
  COMPLETED  // Confirmed; counts to cap
}

enum Gender {
  MALE
  FEMALE
}

enum Standard {
  CLASS_9
  CLASS_10
}

enum DistrictName {
  ANANTAPUR
  SRI_SATHYA_SAI
}

enum VocationalChoice {
  ELECTRICAL
  PAINTING
  PLUMBING
  CARPENTRY
  NOT_INTERESTED
}

model District {
  id              String       @id @default(cuid())
  name            DistrictName @unique
  quotaMax        Int          @default(4000)
  registeredCount Int          @default(0)
  mandals         Mandal[]
  students        Student[]
  createdAt       DateTime     @default(now())
}
model Mandal {
  id         String       @id @default(cuid())
  name       String
  districtId String
  district   District     @relation(fields: [districtId], references: [id])
  schools    School[]
  students   Student[]
  centers    ExamCenter[]

  @@unique([name, districtId])
}

model School {
  id           String      @id @default(cuid())
  udiseCode    String?     @unique
  name         String
  category     String      // Govt, Model, ZPHS, KGBV
  mandalId     String
  mandal       Mandal      @relation(fields: [mandalId], references: [id])
  contactName  String?     // Headmaster / Math Teacher
  contactPhone String?     // Click-to-call number
  students     Student[]
  createdAt    DateTime    @default(now())

  @@index([mandalId])
}

model ExamCenter {
  id            String       @id @default(cuid())
  centerCode    String       @unique
  name          String
  address       String
  mapsUrl       String?
  mandalId      String
  mandal        Mandal       @relation(fields: [mandalId], references: [id])
  capacity      Int
  genderAllowed Gender?      // NULL = Co-ed
  hallTickets   HallTicket[]
}

11. Operational Edge Cases & Mitigations

# Operational Situation Failure Without Architectural Plan Vadaanya 2026 System Mitigation
1 Power cut or network drop midway through form Typed details are lost; rural student or teacher abandons application. Database-Backed Drafts: As each block finishes, data is committed to PostgreSQL under PENDING. Re-entering Aadhaar restores all fields instantly.
2 Teacher registers 35 students using one phone Phone number collision blocks student entry. Phone number is strictly a delivery channel; Aadhaar is the unique key. "Quick Add" keeps school and mandal selections intact.
3 Student attempts duplicate registration Duplicate records pollute database and steal quota seats. Step 0 Gate Check: System checks aadhaarHash immediately and displays: "You have already registered. Reg No: V26-ATP-B0016".
4 50 simultaneous submissions at 3,995 district count Quota overshoots 4,000 due to race conditions. Redis atomic counter + single-statement SQL conditional update: UPDATE ... WHERE registered_count < 4000. Request #4,001 receives HTTP 409.
5 Student misplaces Hall Ticket on exam morning Student is turned away at the exam hall gate. Invigilator Spot-Verification Tool: Center headmaster searches student name or school on admin.vadaanya.org to confirm roll number and seat.
6 Student forgets Registration Number Cannot download Hall Ticket. Dual-Key Recovery: Download portal accepts Aadhaar Number + Mobile Number as an alternate lookup.
7 Schools with low sign-ups (<5 by Nov 10) Unequal participation across mandals. Automated red flag on admin analytics; coordinators tap Click-to-Call to contact headmasters directly.
